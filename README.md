# BogieVision Inspection Console

A browser-based demonstration interface for railway bogie / undercarriage foreign-object inspection. Built with React and Vite. Requires Node.js 18+.

> **Safety notice:** The detection sequence is simulated (hardcoded findings, scripted confidence scores). This is **not** a certified computer-vision system. Connect a validated vision model and follow your railway operator's safety and sign-off processes before using for live operational decisions.

---

## Requirements

- **Node.js 18+** — [nodejs.org](https://nodejs.org/)
- A modern browser (Chrome, Firefox, Safari, Edge)
- For live camera: serve over HTTPS or `localhost` (browser security requirement)

---

## Getting started

```bash
# Install dependencies
npm install

# Start the development server (http://localhost:5173)
npm run dev

# Production build (outputs to dist/)
npm run build

# Preview the production build locally
npm run preview
```

## Features

- **Image sources:** Upload (PNG, JPEG, WebP), live camera (capture frame), built-in demo frame
- **Inspection record:** Train number and location required; explicit Save enforced before scanning
- **Scan gates:** Start detection is disabled unless all three conditions are met (record saved, operator area clear, still image present). Requirements are shown inline — no click-time surprise toasts
- **Image pipeline:** Original → Grayscale → Blur → Threshold → Edge map (10-step checklist)
- **Simulated detection:** Scripted findings with bounding box overlay and simulated confidence scores
- **Quality gate:** Minimum resolution 640 × 360; fails gracefully with a clear message
- **Release / Maintenance decisions:** Recorded immediately, locked after first decision
- **JSON report export:** Includes all inspection fields + `decisionRecord` + `simulationDisclosure`
- **Activity log:** Last 50 events (scan start, decisions, record saves, workspace clears)
- **Theme:** Light/dark; initial value from `prefers-color-scheme`, toggle overrides for session
- **Glassmorphic UI:** Frosted panels, soft gradients, Apple-inspired design, responsive desktop/tablet/mobile
- **Accessibility:** Semantic HTML, `aria-live` toasts, modal focus trap, Esc to close

---

## Simulation limitations

- Detection is **simulated** — findings are hardcoded, confidence scores are scripted
- Camera requires HTTPS or `localhost` (browser security policy)
- No data is persisted between sessions; state is in-memory only
- The exported JSON report is for session reference only and has no legal or operational validity

## Deliberate changes from the original

| Change | Reason |
|--------|--------|
| Explicit Save required before scan (auto-save on scan removed) | Prevents accidental scans with unsaved records |
| Scan gates disable buttons + show inline requirements | Clearer UX vs click-time toast-only feedback |
| Decision locks after first choice until New scan / Clear | Prevents accidental double-decisions |
| "Secure session" → "Local session"; "System online" → "App ready" | Honesty / accuracy |
| "Model confidence" → "Simulated confidence"; "Model review" → "Simulated scan" | Honesty labels |
| Persistent simulation disclosure badge | Required transparency |
| Quality gate validates minimum 640×360 resolution | Real check vs always-pass |
| Blob URL lifecycle managed (revoked on replace / clear / unmount) | Bug fix |
| Camera tracks stopped on End feed, source replace, clear, unmount | Bug fix |
